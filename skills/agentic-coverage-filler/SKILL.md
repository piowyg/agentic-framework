---
name: agentic-coverage-filler
description: Generates coverage fillers — throwaway unit tests that only lift line or branch coverage to the repo's threshold (JaCoCo-style KPI), kept apart from the behavior tests and regenerated, never maintained.
disable-model-invocation: true
---

A coverage KPI counts executed lines, not checked behavior. You write **fillers**: tests whose only job is to execute the code that keeps the build under the threshold. They specify nothing, so they are kept apart, review skips them, nobody copies them, and after a refactor the whole set is thrown away and regenerated. Behavior tests stay what they are; a filler never stands in for one in a report.

## Steps

1. **Read the threshold.** Find the coverage gate in the build (JaCoCo `violationRules`, Jest `coverageThreshold`, `fail_under`, a CI step): the counter (line, branch, instruction), the minimum, the scope (whole project, per package, per class) and the excludes. No gate in the build: ask the human for the number and the counter. Done when you can state the gate in one line.

2. **Find the filler convention.** If `.agentic/standards/testing.md` has a `Coverage fillers` section, follow it. Otherwise agree one with the human and use it from here on: a name suffix every tool can glob (`*CoverageFillerTest`, `*.coverage-filler.test.ts`), a tag where the framework has tags (JUnit `@Tag("coverage-filler")`, pytest marker), and a home — either a dedicated directory or source set, or the same package as the code it covers when the tests need package-private access.

3. **Start clean.** Delete every existing filler. A filler is regenerated, not fixed: the new set comes from the current code only. Run the coverage task on the behavior tests alone and record the value. Done when no filler is left and you have the baseline.

4. **Pick the gaps.** From the coverage report, list the uncovered code by size, largest first, within the gate's scope and excludes. Choose the fewest classes or modules that lift coverage to the threshold plus a margin of two points, so the next small change does not fail the gate. Generated code, configuration and `main` wiring belong in the gate's excludes rather than in fillers: propose that change to the human, do not make it.

5. **Write the fillers.** One filler file per covered unit, with this header comment:

   > Coverage filler, generated by agentic-coverage-filler. It executes code for the coverage gate and specifies no behavior. Regenerate the set instead of editing or fixing this file, and do not use it as an example of a test.

   Drive the code through its public methods with the simplest inputs that reach the uncovered lines and branches. Assert only what holds as long as the code runs at all (it returns, it throws the declared exception); an assertion on a computed value turns a filler into a fragile behavior test. Real collaborators where they are cheap, plain stubs where construction needs them. Nothing slow, random, time-dependent or networked.

6. **Prove the gate green.** Run the full test task twice; both runs green and the coverage value identical. Done when the gate passes with the margin.

7. **Record the convention.** Add or update the `Coverage fillers` section in `.agentic/standards/testing.md` (create the file if missing):

   ```markdown
   ## Coverage fillers

   Tests named `*CoverageFillerTest` (tag `coverage-filler`, in <home>) exist only for the coverage gate
   (<counter> ≥ <minimum>). They specify no behavior:
   - Review does not judge them, and they are not an example of how to test here.
   - A filler that fails after a change is deleted, not fixed; the set is regenerated with agentic-coverage-filler.
   - Behavior tests for new code are written as usual, whatever coverage the fillers already give.
   ```

   Keep it prose, not a numbered rule: it scopes the other rules rather than adding one.

8. **Commit and report.** One commit with the fillers and the standards edit, apart from any behavior change. Report the gate, coverage before and after, the number of fillers, and the classes covered **only** by fillers: that list is the behavior-test debt the KPI hides.
